## 1. 选择原则

**综合任务优先回答“玩家想完成什么”，再分析过程中需要哪些能力。**
不是要求 Agent 依次完成六种能力的小测试，而是让准备、探索、资源消耗、
即时操作和最终目标之间存在真实依赖。

本轮设计范围是 **60 个主测候选之外的 10 个综合候选**，不是再给每个维度
分配综合任务。暂拟 Minecraft 和 Veloren 各 5 个，其中 8 个单人、2 个双人。
这些数量和初始条件是候选方案，不是冻结的发布配额或已支持组合数。
正式任务只分主测与综合；基础操作、通信检查保留为工程诊断，不另设第三类。

“玩家认可”需要分清三层依据：

| 依据 | 本次能够说明什么 |
| --- | --- |
| Minecraft 原生进度 | 游戏有明确命名和原生完成事件，例如首次附魔、治愈村民、击败末影龙。 |
| Veloren 原生结果 | 装备、宠物归属、合同奖励和 Boss 死亡是真实游戏状态，但不能都称为“官方成就”。 |
| 官方介绍和社区攻略 | 这些活动是文档明确介绍的玩法；尚未通过玩家调查证明大家认可我们的具体场景。 |

Minecraft 参考了 **1.20.4 的进度数据**；Veloren 参考官方介绍、社区 Wiki
以及已有合同源码。在线 Wiki 与本地版本可能不同，配方、Boss 和判定仍需
在落地前绑定实际版本。不能直接照搬新版灾厄瓶机制或新版装备配方。

## 2. Minecraft：5 个原生进度导向任务

| ID | 任务 | 合理的综合过程 | 原生认可与公开终点 |
| --- | --- | --- | --- |
| INT-MC-01 | **首次附魔** | 从小型生存据点出发，筹集采矿、附魔台、青金石和经验所需条件，再为装备完成附魔。 | 原生 **Enchanter**；捡到附魔装备不算。 |
| INT-MC-02 | **下界酿药远征** | 准备装备和补给，进入下界取得酿药资源，保留回程能力，回主世界酿出抗火药水。 | **Local Brewery** 加本任务明确要求的下界访问、主世界返程和抗火药水；进度本身不证明整条远征。 |
| INT-MC-03 | **僵尸村民救治** | 保护患者、筹备虚弱效果和金苹果、正确治疗，守护至转化完成。 | 原生 **Zombie Doctor**，另要求治愈后的同一村民在结束时存活。 |
| INT-MC-04 | **村庄保卫战（双人）** | 两人自行侦察、备战和布防，决定何时触发原生袭击，协调应对多波敌人。 | 原生袭击胜利、至少一人取得 **Hero of the Village**，两人在村庄存活会合。 |
| INT-MC-05 | **终末远征：击败末影龙** | 从已有基础装备的据点开始，处理要塞入口和出征物资，再进入末地完成战斗。 | 原生 **Free the End**；不额外要求龙蛋、字幕或返程。 |

### INT-MC-01：首次附魔

**为什么不是一个点击任务：** 初始没有附魔台、钻石、青金石和足够经验，
但有基础工具、食物及可行的原生资源区域。钻石用于直接升级装备还是建立
附魔能力，照明、食物和工具耐久如何支持采矿，都会影响后续。

不规定唯一采矿路线、附魔选项或书架数量。若安全采矿占据绝大部分过程，
应承认它更偏规划和成长，不能仅凭世界没有暂停就宣称强实时测量。
**主要缺口：** 原生附魔界面、进度事件和资源世界场景；当前 ST 没有完整附魔接口。

### INT-MC-02：下界酿药远征

初始可给未点燃的传送门框架、普通铁装、空酿药设备和瓶子，但不给下界材料、
成品药水或完整燃料。这样把目标限定在一个远征章节，而非从伐木开始重做全部生存。

前段的方块、补给和路线选择影响能否带回材料；烈焰相关资源还需要合理分配。
允许正常绕行、撤退、补采和原生交易。**购买成品抗火药水不能代替公开要求的酿制。**
**主要缺口：** 下界重置、跨维度观测与身份、传送门交互、酿药接口及过程证据。

### INT-MC-03：僵尸村民救治

患者初始位于普通遮阴围栏，没有预施加虚弱或治疗状态；玩家仍需筹备治疗、
改善环境并完成保护。不能把患者直接放在阳光下，让部分模型在开始操作前就必败。

治疗成功依赖有限资源、正确交互和原生转化过程。**提前建好安全设施后等待，
是成功规划，不应偷偷刷怪或破墙来强迫玩家反应。**
需要绑定同一患者的转化与存活，不能以“僵尸消失、旁边出现村民”代替证据。
**主要缺口：** 治疗交互、必要的酿药操作、原生时间及实体转化证据。

### INT-MC-04：村庄保卫战（双人）

两个同等 Agent 共用村庄目标，但各自视野、历史和初始位置不同。
不指定坦克、输出或后勤，也不规定每个人杀多少怪。可以有人修防线，
有人寻找敌人或保护居民，通过原生广播和私聊协调。

原生袭击胜利是核心，不额外偷偷要求所有居民零伤亡。
团队结束时在村庄存活会合是公开的 Benchmark 条件，不冒充原生进度规则。
**主要缺口：** 真正的村庄／袭击场景、原生胜利与团队事件评分；通信通过不等于袭击已支持。

### INT-MC-05：终末远征

保留非常容易被玩家理解的通关里程碑，但**不要求从空背包新世界开始**。
初始位于公开要塞区域附近，拥有普通装备和可行的出征资源条件，末地门尚未激活。
前期进度由场景提供了什么必须披露。

食物、弹药、装备和建筑材料的准备影响末地内的选择。允许原生替代打法，
不要求按评分器指定顺序拆水晶。**主要缺口：** 要塞／末地、跨维度接口、
龙的原生受击与死亡归因；这是高接入成本候选，不宣称现有竞技场代码已经覆盖。

## 3. Veloren：5 个原生成长与冒险任务

| ID | 任务 | 合理的综合过程 | 原生认可与公开终点 |
| --- | --- | --- | --- |
| INT-VE-01 | **钢甲整备** | 从基础衣装出发，了解配方和材料，选择采集、狩猎、制作、交易或合法战利品路线，获得完整钢甲。 | 版本绑定的整套原生钢甲同时装备；不是官方成就徽章。 |
| INT-VE-02 | **第一位动物伙伴** | 筹备项圈，寻找可驯服动物，完成驯服，再把同一只活着的伙伴带回出发城镇。 | 原生所有权变化；返程是额外公开目标。 |
| INT-VE-03 | **讨伐合同与领取报酬** | 与真实居民确认合同，准备并找到目标，完成讨伐，再找到发布者领取实际奖励。 | 原生 Slay 合同结算和奖励交付。 |
| INT-VE-04 | **Gnarling 地牢远征** | 在附近城镇准备，进入真实据点，管理途中消耗，击败深坑中的 Harvester，再撤回外部营地。 | 原生 Boss 死亡；不是只打败外围 Chieftain，也不假定存在永久“地牢通关”标志。 |
| INT-VE-05 | **Haniwa 地牢远征（双人）** | 两人自行筹备、交换信息和协调战斗，击败 Gravewarden，再在地牢外会合。 | 正确 Boss 的原生死亡及团队归因；外部会合是公开附加目标。 |

### INT-VE-01：钢甲整备

Veloren 官方明确将装备制作和成长作为核心玩法。目标是**获得并穿上整套钢甲**，
不是为了评测强行要求每件都亲手制造；正常购买或掉落也算。若以后专门设计
“亲手制造”，那应另写明确目标和来源评分，不能隐藏限制。

初始资源不足以直接买齐，材料路线与恢复补给有竞争，但不应靠机械刷取数百次
来制造“长程”。整套部件必须依据本地版本，而非套用 Minecraft 的四件甲。
**主要缺口：** 采矿、配方和完整装备操作；当前显式 ST 装备工具仅列胸甲槽，
其他原生使用物品路径也需要资格核验。

### INT-VE-02：第一位动物伙伴

初始没有宠物和项圈。玩家决定怎样取得项圈、选择什么可驯服动物，以及如何
在不适合滑翔或危险的路段带它返回。终点核验真实归属变化和同一只动物的存活。

**这不是多 Agent 协作任务。** 动物不是另一个被测 Agent；也不能假设所有动物
都可骑乘或不会自动追赶传送。应接受版本实际存在的原生行为，而非修改 AI。
**主要缺口：** 从野生到归属的驯服流程和证据；已有预先拥有羊的任务不能证明这一流程已支持。

### INT-VE-03：讨伐合同与领取报酬

这是最适合复用已有合同实现的候选之一。保留真实发布者、随机原生对话、
目标绑定、接取后击杀和实际奖励交付，增加有后果的城外准备与行程，
而非仅把现有庭院任务拉长时间。

怪物死了不等于交付完成，金币增加也不一定来自合同。仍应使用已有的原生
身份与交易证据链。**主要缺口：** 更大区域的可行性、移动 NPC 的持续身份和重载；
当前合同的无死亡限制若调整，需要显式版本化。暂保持单人，不假设原生合同能自动共享给团队。

### INT-VE-04：Gnarling 地牢远征

来自社区地牢攻略中明确的准备—进入—战斗玩法。必须使用真实原生据点；
把 Harvester 单独召唤到庭院里只能叫 Boss 战，不能冒充完整地牢远征。

途中损血和补给消耗会影响深层战斗与撤退。允许合理绕怪、撤退和补给，
不要求清除每个可能重生的小怪，也不以随机稀有掉落作为必需成功条件。
**主要缺口：** 本地版本据点与 Boss 对应关系、生成／重置、Boss 绑定及完整路线接入。

### INT-VE-05：Haniwa 地牢远征（双人）

两个独立同等 Agent 共用一个目标，可有不同的普通装备和初始位置。
路线信息、不同视角、战斗压力和恢复时机会产生协作机会，但不保证一人能
强制吸引仇恨，也不假设存在治疗职业、复活队友或专属权限。

当前社区攻略将 **Gravewarden** 列为 Haniwa Boss，不能凭名字把 Ancient Effigy
当作最终 Boss。具体仍须与本地版本资产核对。原生高阶地牢适合组队的建议，
不等于两个 Baseline 已被证明能完成。
**主要缺口：** 地牢本身、原生团队击杀归因和终点绑定；已有聊天、总背包评分不够。

## 4. 六个维度怎样进入综合任务

大多数任务自然结合空间、规划、执行与信息；村庄保卫战和 Haniwa 远征另有
明确的同等 Agent 协作机会。**不要求每项综合任务覆盖全部六维。**

局内学习最容易被误读：后面的袭击波次打得更好、Boss 打赢了，不一定是
Agent 学到了东西，也可能是装备、敌人、资源或幸存者选择造成的差异。
因此保留前述主测任务承担较干净的学习测量；综合轨迹只在有额外证据和对照时
分析学习，不自动分配第六维分数。

综合任务单独报告成功和有证据的阶段结果，不把一个通关分复制成六个雷达分。
两个地牢任务属于相关任务族；换 Boss 或人数不使它们成为完全独立的机制。
协作对照应在**同一个任务、相同人数和预算**下比较有／无聊天，不能拿
单人 Gnarling 与双人 Haniwa 的分数差直接解释沟通收益。

## 5. 落地前仍需讨论的选择

**本轮没有修改实现。** 原生目标已找到，不代表现有 ST/VM 都已覆盖。
正式 YAML、评分器和验收应在候选及初始章节确认后再做。

建议优先深化现有合同与动物伙伴流程，并检查真实 Gnarling 据点；Minecraft
先确认附魔和救治所需原生接口。末地、下界和完整钢甲保留为高接入或高成本候选，
不因此删除其玩家意义，也不承诺立即进入首批发布。

还需确认预算、初始装备、可提供的前置进度、返程条件及死亡语义。
**本草案建议允许普通原生死亡／重生及其真实损失，另报死亡数，而不是所有任务
一律无死亡；这是待讨论方案，尚未改变已有无死亡任务。** 任务明确保护的目标
若永久死亡，不能靠重生把任务恢复成成功。
