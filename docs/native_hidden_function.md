# Approved native function-replication prototype

The known stairs/roof answer is replaced by a native reference circuit and two
public construction panels. The first feasibility family is **AND/OR only**;
XOR and A-AND-NOT-B are not implemented or claimed. Public diagrams disclose
both candidate gates and their connection sockets, but not the reference
selection. A real protected wire connection selects the reference function.

The two panels have mirrored layouts. Ordinary conductive blocks connect
candidate outputs to actual lamps. Mechanical flags expose the same outputs
through ordinary public block observations without adding an observation API.
The prototype retains twelve supplied blocks and a six-removal ceiling.
All four input cases must agree with the reference under the final construction.
An observed intervening construction change invalidates earlier case evidence.

The reference vault has a deep native bedrock buffer. Input/output signals
cross its solid wall through native powered blocks rather than crawlable cable
holes. No hidden threshold/function identifier is inserted into public tools,
task text or the public fixture manifest.

## Genuine native instance family

The revised canonical fixture includes `native-function-variants.json`.
Before any episode starts, the binding validates two distinct native AND/OR
worlds with identical public manifests and selects one with
`secrets.randbelow(2)`. It records the selection and fixture fingerprint only
in private evidence. There is no outcome-dependent resampling. A missing
manifest, duplicate function or inconsistent public contract fails admission;
the revised learning task cannot silently fall back to fixed AND.

Both functions are real ordinary redstone circuits. The final objective uses
the four actual native reference outputs retained from authoring preflight,
not a private chosen-function label. The original connection is also checked
against those measurements. Initial authoring normalizes OR world time to the
AND fixture; no active gameplay clock or friction is modified. Public task
wording, controls, supplied resources, removal ceiling and optional-probe rule
are identical across instances. No new server hook is introduced.
